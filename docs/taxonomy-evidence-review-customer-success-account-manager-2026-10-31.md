# Evidence review — "Customer-Success-Account-Manager" (read-only, no changes applied)

2026-10-31 · read-only production evidence review per Deep's authorization. **No denylist, engine,
test, or scoring changes made.** No database writes, commits, pushes, PRs, merges, or deployments.
Method: SELECT-only queries against production via PostgREST (service-role key), from within
`fix-taxonomy-skill-collision-wt`; two temporary scratch scripts were written for the queries and
deleted immediately after use.

## 1. Representative job titles and required-skills clusters

169 active opportunity rows currently carry this tag (count grew from the 124 seen in the prior
pass's catalog scan — live ingestion between the two reads, not a measurement error). Full title
list inspected; representative sample:

- "Account Manager, Client Development & Renewals (Texas)" @ SentinelOne
- "Customer Success Manager (Higher Education)" @ D2L
- "Client Success Manager, Scale" @ FMG
- "Strategic Customer Success Manager" @ LaunchDarkly
- "Customer Success Manager, Key Accounts" @ Sprout Social
- **"Customer Success Account Manager" @ Redpoint Global Inc.** — the one row where the tag's exact
  phrase *is* the posting's literal job title.

**Across all 169 rows, only 1 has a job title that literally matches the tag's phrase.** The other
168 are titled either "Customer Success Manager" / "Client Success Manager" (the large majority) or
"Account Manager, ..." (a smaller group) — never "Customer Success Account Manager" itself.

## 2. Candidate-side self-reported skills (no PII exported)

Queried `profile_skills` for `Customer-Success-Account-Manager` (exact and space-separated), plus
`Customer-Success-Manager` and `Account-Manager` for comparison. **Zero rows for all four probes.**
No candidate in production currently self-reports any of these as a literal skill — same
zero-current-impact finding as the TAM/ABM review. Query results contained no name, email, or resume
text; only `skill_name`/`years_used`/`is_primary` were requested, and the result set was empty.

## 3. Title-expansion collision mechanism — same as Account-Executive, NOT the same as TAM/ABM

Co-occurring tags across these 169 rows (top 3): `Customer-Success-Manager` (158×, 93% of rows),
`Account-Manager` (101×, 60%), `Customer-Success` (99×, 59%).

This is the decisive finding, and it points the opposite direction from TAM/ABM: `Customer-Success-
Account-Manager` is overwhelmingly a **synthesized hybrid tag** — generated by combining the
`Customer-Success-Manager` and `Account-Manager` role-concepts into one blended tag — not itself a
standalone job title. That's the *same* title-expansion mechanism that produced the original
confirmed `Account-Executive` collision (a tag generated from role-concept combination, not naming a
distinct profession) and the explicit opposite of what the TAM/ABM review found (where the exact tag
phrase was itself the real posting's literal title at CDW, Samsara, Tines, EverCommerce, etc., in the
large majority of cases).

## 4. Legitimate-signal-loss examples

**None found.** For 168 of the 169 rows, the posting's real requirement is already fully represented
by tags that are *not* denylisted (`Customer-Success-Manager`, `Customer-Success`, `Customer-Success-
Specialist`, etc. — none of these contain both an account-word and a title-word) or that are
*correctly* denylisted already as part of the confirmed `Account-Executive`/`Account-Manager`
collision (`Account-Manager` itself). Filtering `Customer-Success-Account-Manager` specifically costs
nothing beyond what's already lost by the (confirmed-correct) `Account-Manager` filtering on the same
postings.

The one exception — Redpoint Global's "Customer Success Account Manager" posting, where the tag *is*
the literal title — is a single row (<1% of the 169) with zero candidates currently affected either
way (finding 2). It's a real but extremely thin edge case, not a pattern.

## Limitations

- Zero-candidate-impact findings describe the *current* production state, not a hypothetical future
  candidate who legitimately lists this skill — same caveat as the TAM/ABM review.
- Did not exhaustively read all 169 full description texts (only titles + tag clusters) — the
  co-occurrence pattern across all 169 and the full title list is conclusive enough for the
  recommendation below without that additional read.
- Row/tag counts will keep drifting with live ingestion; treat the exact numbers as point-in-time.

## Recommendation

**Do not carve this tag out.** Unlike `Technical-Account-Manager` and `Account-Based-Marketing-
Manager` — both confirmed to be genuine, independently-titled job categories on real postings — 
`Customer-Success-Account-Manager` is, in 168 of 169 observed cases, a generated hybrid tag combining
two already-represented role-concepts, not a distinct profession. It fits the *original* collision
pattern (title-expansion producing a tag that doesn't name a real standalone job) rather than the
TAM/ABM exception pattern (a tag that names a real standalone job). Leaving it denylisted costs
nothing (finding 4) and stays consistent with the module's own stated design principle: extend the
carve-out list only with the same kind of named, evidence-grounded case as TAM/ABM — this one doesn't
meet that bar.
